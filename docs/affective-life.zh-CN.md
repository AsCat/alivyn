# 情感生活与行为连续性（RFC 03）

状态：部分实现。`actor_v1` 会把本轮关注点、角色自己的愿望与情绪、近期连续对话及有来源的未完话题交给表达层；短期记录会过期，也会随遗忘清除。真实交流涉及过的世界目标产生新事件时，可生成一次有来源的主动联系候选，由现有联系策略决定是否发送。长期观点演化和通用设备能力仍是设计目标。

## 为什么要做这一层

意续目前有持久记忆、关系阶段、汐湾事件和“先决定行动、再生成话语”的链路，但关系主要按交流次数和天数晋级；角色没有一个由经历改变、随时间演化、并在下一轮影响行为的情感状态。因此，即使一句回复没有事实错误，仍可能像照着规则关心用户。

参考项目提供了一个可借鉴的方向：[AstrBot 的群聊增强插件](https://github.com/Him666233/astrbot_plugin_group_chat_plus)将接话判断、上下文、情绪提示、主动发言与打字延迟分开；[better-dsh-pet](https://github.com/ysppwn721/better-dsh-pet) 让心情影响空闲动作和气泡。意续借鉴的是**内部状态改变行为**和分层决策，不直接复制这些项目的代码或用“聊天 +1 好感度”代替关系。

## 模型

```text
有来源的事件 + 时间推进
    → 角色评估：这件事与我的价值、目标和关系有什么关系？
    → 状态投影：稳定特质 / 当前关注 / 情感倾向 / 对此人的态度 / 未完事项
    → 行动选择：回应、分享、追问、不同意、修复、暂不联系
    → 自然表达 → 发送结果与反馈回写
```

| 状态 | 持续时间 | 作用 |
| --- | --- | --- |
| 稳定特质 `Traits` | 随角色版本演化 | 她重视什么、对什么敏感、怎样处理分歧；不会因一次聊天重写。 |
| 自身目标 `Drives` | 跨天 | 例如查清录音授权；决定她在用户不在时会注意和推进什么。 |
| 关系认识 `RelationalView` | 跨轮、可修正 | 对这个人的了解、信任、保留意见、明确边界和共同经历；与“交流次数阶段”分开。 |
| 当前倾向 `AffectiveEpisode` | 分钟至数天 | 由具体事件引发的好奇、放松、犹豫、烦躁、欣慰等，可并存，有强度、证据和衰减时间。 |
| 未完成的事 `OpenLoop` | 到解决或过期 | 未回应的问题、角色自己的失误、仍在推进的世界冲突；影响下一次关注点。 |

情感状态是**对经历的角色化解释**，不是模型对真实感受的证明。用户的情绪只能在用户明确表达或足够具体的上下文下作为不确定推断；不能把沉默、重复问候或回复间隔解释为冷落。时间流逝可以让短期倾向回归基线，但不能凭空制造怨气或亲密。

## 事件与更新契约

每次状态变化需写入可重放的简短评估记录：`event_id`、事件来源、角色关注的事实、受影响的价值或目标、状态变化、置信度、有效期、修正来源。模型可以提出评估，程序校验事件存在、来源类型、影响范围和过期时间后提交；评估不能直接创造新的现实事实或汐湾经历。用户纠正、遗忘和明确边界应使相关推断、主动联系候选与生成上下文同步失效。

情绪变化不等于话语中的情绪词。每种状态必须有可观察的行为后果，至少改变一个选择：要不要提自己的事、是否追问、是否坦诚表达不同看法、回复篇幅、是否主动联系及其时机。语言层只得到本轮有关的状态与证据，不读取整套内部数值，也不把“我现在焦虑值 70”之类的诊断直接说给用户。

## 三段跨轮例子

1. **误解与修复：** 她把一个普通问候读成用户有事求助；用户说“你在说什么”。事件记录的是她自己的误读。下一轮优先简短认错，之后一段时间减少未经根据的动机猜测；用户不因此被标记为生气。
2. **自己的世界：** 她与林澄对录音授权有分歧，世界事件使她更关注“说话前把事实弄清”。用户聊到承诺时，她可以据此表达谨慎的看法；用户只说“你好”时，不必汇报档案工作。
3. **短暂失联：** 电脑休眠后，角色知道有时间断层；与上次未完话题相关的关注可保留，短期情绪衰减。她不声称看到了用户的生活，也不因为用户没有回来而自动委屈。

这些例子使用同一个评估和决策过程，不设置输入句子的专用回复模板。

## 实现切片和验收

1. 在现有事件账本旁增加版本化的评估事件和状态投影，支持重放、进程重启和同一事件去重；先把现有关系阶段作为输入，不重算历史情感。
2. `actor.Frame` 已接收近期对话与有来源的未完事项；`Decision` 记录当下行动、关注点、角色自己的愿望和情绪。表达层接收这些短线索及有序近期对话，但关于事实的断言仍需选中的证据。尚待实现的是长期、可重放的观点演化。
3. 世界循环已在真实共同话题取得新进展时生成联系候选。陌生关系、追赶生成的旧事件和用户明确要求距离时不生成；用户先发消息会取消候选。发送仍以暂停、免打扰、频率和现实边界为先。不要把“想念”“担心”作为突破联系边界的理由。
4. 用完整对话时间线验收：重复问候、角色误读、用户纠正、观点分歧、角色世界事件、数日离线、边界变化、模型切换。检查状态确实改变后续选择、变化有事件来源、过期后不会僵持；真人盲评自然度及人物一致性。通过后再让已配对飞书实例试用，并保留回滚路径。

验收重点是“能说清她为什么这样做，并看到之后真的有所不同”。单句更像人、随机延迟、表情或更大的提示词都不算这一层的完成。
