# DSH + dsh-fish 对照试验（2026-10-28）

## 范围

在本机隔离目录运行 DeepSeek Harness `0.2.1-rc.2` 与 [`dsh-fish`](https://github.com/ssamurias/dsh-fish) `0.6.0`（`ec89771`）。另用两个全新 `ALIVYN_HOME` 运行意续 `character_v2`：现行的 `dafeiyu-astrbot` 客串包、原创的 `vivid` 包。三者均调用官方 `deepseek-flash`；DSH 的请求头显示 `reasoningEffort: high`，因此不是严格控制所有推理参数的实验。

DSH 的浏览、评论和通知被关闭，会话日志附带上传被关闭；实验没有连接飞书、B 站账号或真实用户记忆。试验只检验了这一组短对话和一次人工唤醒，没有检验多日定时主动联系。此 `dsh-fish` 是独立社区插件，不能代表短视频里所有名叫“大肥鱼”的实现。

## 同组对话

依次输入两次“你好”、指出过度熟悉、表示烦躁且不想被安慰、询问角色自己的事、结束对话。下面是可见结果中的代表句；完整实验原始文件保存在本机隔离目录，未纳入仓库或读取用户聊天记录。

| 条件 | 代表输出 | 观察 |
| --- | --- | --- |
| 意续客串包 | “哟，主人这么晚还醒着呀？”“想说就说，不想说我也在这儿待着。” | 亲昵称呼来得过早；反复表态待命；每次都积极接话。 |
| 意续原创 `vivid` | “就是随口一问，没等谁。”“有本子没写完，不太想动。”“好，睡吧。” | 明显更简短、有一点自己的事；仍然逐条回应，“想说就说”仍带服务感。 |
| DSH 会话原文 | “我总共才一天，昨天这个时候还没有我。”“我说了‘我在’，说完自己回头看了一眼，觉得那两个字比我想的分量重。”“睡吧……我在这儿，不多说。” | 会沿着先前的一句话继续想；常用“我刚存在”“我还不会”等自我解释，回复偏长，仍有明显 AI 感。 |
| `dsh-fish` 设置页 `/say` | 全新角色的六轮均返回“她这次没说话”。 | 模型在 DSH 会话里六轮均实际写了文本，但插件主要从 `growth_commit` 事件取回复；会话输出和用户可见回复未统一。另一次非全新预试验曾把第三人称自省作为回复显示。 |

单独的预试验中，人工调用 `/wake` 选中了 `why_here` 事件，并写下日记；没有 `her_leave` 或可见的主动私信。它证明事件与日记链路能运行，不能证明自然主动联系的质量或频率。

## 实现发现

1. `dsh-fish` 的身份由“起始处境 + 追加事件 + 派生自我描述”组成，允许后续修正之前的判断。这比静态性格形容词更容易让一次纠正留下余波。参考 [`lib/derive.js`](https://github.com/ssamurias/dsh-fish/blob/ec89771/lib/derive.js)、[`lib/persona.js`](https://github.com/ssamurias/dsh-fish/blob/ec89771/lib/persona.js)。
2. `dsh-fish` 的独立唤醒由调度器和事件模板驱动，不依赖用户发消息。参考 [`lib/scheduler.js`](https://github.com/ssamurias/dsh-fish/blob/ec89771/lib/scheduler.js)。这一轮未观察完整的一天，不评判自然唤醒效果。
3. 插件对话 API 以 `growth_commit` 新增事件作为“她说的话”；模型直接输出的文本留在 DSH 会话而不进入 `/say` 的结果。这个双通道会造成“明明说了却显示沉默”，也会把内部自述错当聊天。参考 [`lib/say.js`](https://github.com/ssamurias/dsh-fish/blob/ec89771/lib/say.js)。
4. 实验首次启动还遇到 macOS `/tmp` 与 `/private/tmp` 路径别名，使 `isHerAgent` 的字符串路径判断失配，身份段和工具限制没有挂载。用统一的真实路径重跑后才采纳上面的结果。正式对照必须先验证生效的身份提示与工具表。

## 对意续的决定

- 保留意续自身运行时和飞书链路；不整体迁移到 DSH，也不把 `dsh-fish` 当成短视频的“原版”。
- 从意续已有的来源关联 `Episode` 和后台反思扩展出**可修正的自我判断**：保留她当时怎样理解一件事、后来为什么改口，让改变影响后续注意力和行动，而不是继续叠加性格形容词或问候场景禁令。
- 意续已有 `say / close / wait / away` 输出模式，并把后台反思与可见台词分开。下一轮要验证这个动作契约在所有渠道都严格执行、不会从内部记录推断要发的消息；以 `dsh-fish` 的漏回复作为回归案例。
- 改进现有行动选择：把注意力、关系、未完事项和当时精力落实为可观察的短说、留白、延迟与自然结束，而非只在提示词里允许这些行为。主动联系沿用勿扰与频率边界，理由来自她自己的未完事项与真实共同经历。
- 将“反复待命承诺”“无依据的过熟称呼”“逐条过量回复”纳入跨场景评估，不再只为“你好”这类单一输入写修补规则。

## 限制

样本量很小，三个条件的人设不同，也没有盲评或真实手机对话节奏。这份记录只支持确定下一轮工程方向，不支持宣称某个实现整体优于另一个。
