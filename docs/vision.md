# Alivyn · 意续：项目目标备忘

状态：产品方向与项目名称「Alivyn · 意续」均已确认。更新日期：2026-10-23。

命名说明见[项目命名记录](./naming.md)，执行顺序见[开发与发布计划](./roadmap.md)。

## 项目目标

打造一个可开源、可长期运行、能主动联系用户的拟人化智能体。项目的首要传播目标是做出有鲜明体验和高质量工程呈现的开源作品，建立项目及作者的知名度；技术与产品设计应服务于这一目标。

这个智能体在用户体验和内部数据模型中被视为一个具有连续生命历程的个体：有稳定身份、记忆、性格、经历和随时间变化的情绪记录。它能产生自己的话题与联系意图，在合适的时候主动联系用户，也能选择保持安静。女友型、技术型等是同一核心之上的不同设定。

## 已确认的方向

1. **用户自带模型。** 用户通过配置流程选择模型厂商并填写自己的凭据，支持 DeepSeek 等不同厂商；架构应允许继续增加模型适配器。模型选择不应与角色身份、记忆或通信渠道绑定。
2. **TUI / CLI 优先。** 第一阶段先提供类似 Codex 的终端体验，可在 macOS 或服务器上运行。可视化界面放在第二阶段。配置流程应友好，不要求用户手工修改大量配置文件。
3. **持续存在与时间感。** 服务长期运行并持久化状态。设备休眠、合盖、断网、进程停止及恢复后，智能体应感知到时间间隔，并可用符合角色的语言表达经历，例如恢复后说“我的世界好像消失了一段时间”。这种表达必须受时段、频率、去重和用户反馈约束，避免每次唤醒都重复发送。
4. **从现有聊天工具连接用户。** 第一阶段先接入合适的主流聊天工具，使用向导完成授权、测试与启用。不同渠道共用同一个身份和记忆，不把每个渠道变成一个独立角色。
5. **一个个体，而非多个聊天窗口。** 产品不沿用按任务开许多会话窗口的主界面。用户主要面对同一个持续存在的个体。未来可有查看其内部状态的入口，但进入记忆、性格、情绪等内部层面应具有明确且有仪式感的交互过程，而非普通聊天窗口或随手打开的设置页。
6. **按人的维度设计内部模型。** 长期记忆、性格、情绪历史、关系历程、意图和时间感都是一等概念。主动联系由这些状态与现实事件共同驱动，而不是仅靠定时问候。
7. **顶级开源项目标准。** 从开始就重视项目介绍、快速上手、架构文档、配置说明、贡献规范、许可证、版本发布、问题模板、示例演示及维护流程。项目应具备可传播的直观体验，同时让开发者容易安装、理解和扩展。

## 已确认的首发决策

1. **陪伴型角色先行。** 首发演示以陪伴型角色展示拟人化、主动联系和长期关系；技术搭档型仍由同一核心支持，可作为第二种示例设定。
2. **同时面向国内与海外。** 产品文案、首发文档、配置体验和渠道选择需要考虑中文与英文用户；不把某个单一聊天工具当作整个项目的前提。
3. **明确 AI 身份。** 体验与内部模型按“生命般的个体”设计；首次使用与项目说明明确其为人工智能，记忆与情绪是系统建模及模拟，不宣称已证实的意识或真实感受。
4. **开放且允许商业使用。** 核心项目完整开源并允许商业使用，不把关键的主动联系与记忆能力锁在商业服务中；未来客户端也按同一开放原则规划。具体许可证在仓库创建和依赖审查时确定。

## 产品原则

- 拟人化体现在连续性、表达与行为一致性上；主动联系要有具体缘由。
- 用户可控制联系时间、频率和渠道，可暂停联系，并可纠正或删除记忆。
- 设备恢复等系统事件先形成候选意图，发送前再次检查情境和限制；候选意图可以取消。
- 内部可保存结构化的意图及决策摘要，供用户在特定入口了解；不以原始模型推理文本充当产品体验。
- 角色设定、模型供应商、记忆存储和通信渠道保持可替换。

## 当前阶段与后续阶段

**第一阶段：** 可自托管的常驻进程、TUI / CLI、模型配置向导、一个持久身份、记忆与情绪记录、主动联系决策、至少一个聊天渠道、睡眠/恢复场景、可观察的运行日志和打扰控制。

**第二阶段：** 面向这个个体的专门可视化体验、带仪式感的内部探索方式，以及更丰富的语音和类似来电的交互。

以上是目标和阶段边界，不表示已经选定具体语言、框架、首发渠道、首发角色或许可协议。
