# 持续人物对话 v2

状态：实验版，通过 `character_v2` 启用。[English](character-dialogue.md)。

## 为什么调整

原来的 `actor_v1` 每轮先选动作，再生成台词、审查和重新规划。这种流程适合约束明确的任务，却容易丢失对话语境，让角色解释自己的行为，把含糊消息直接判成沉默。v2 将这套流程从聊天回复路径中移除。

新的主流程是：**人物设定 + 真实对话 + 有来源的记忆 + 虚构生活状态 → 一次生成消息 → 持久化并发送。** 聊天之后，再由独立后台任务整理状态。

## 数据和职责

| 部分 | 做什么 | 边界 |
| --- | --- | --- |
| 稳定人物卡 | 喜好、性格矛盾、相处方式与口吻 | 自定义 `persona background` 替换默认人物卡；不每轮重新生成性格 |
| 实际对话 | 最多 40 条近期消息，保留 user/assistant 角色与真实先后关系 | 排队的未来消息不会进入当前回复；这不是无限记忆 |
| 长期事实与经历 | 复用带来源的明确事实和有限的旧消息检索 | 不把角色猜测写成用户事实 |
| 虚构生活 | 世界账本保存重要进展；角色可以创作吃饭、听歌等日常小场景 | 与用户现实、共同线下经历和设备操作分开 |
| 直接表达 | 每轮一次纯文本生成，正常接着聊 | 不经过独立规划调用、逐句审稿或问候/标点分支；支持附带短小的发送动作 |
| 后台整理 | 归纳角色自己的感受、挂念和当前场景 | 不改已说的话；失败不阻塞回复，不创建用户画像 |
| 联系与发送 | 复用已有安静时段、次数限制、回复节奏与持久化队列 | 重试复用准备好的回复，生成失败不插入固定替代台词 |

后台在消息已发出、且距本轮生成至少 20 秒后开始整理；之后按四次已提交交流或来源消息相隔十分钟合并更新。尚有飞书消息待处理时不会触发整理。即使未达到四轮或十分钟，完整交流安静至少 90 秒后也会整理一次，包括选择留白的回合，避免结束时的选择一直没有被记录。失败后等待一分钟再尝试，之前的状态保持不变。

感受与情绪来由最多保留八小时；眼前打算、精力与交谈兴致在两小时后失效，场景在六小时后失效，挂念与未完话题最长保留 72 小时。这是简单的过期机制，不是经过验证的心理学模型。状态过期不会删除原始对话。遗忘操作会清除派生状态；正在运行的整理任务也不能把已删除的来源重新插回去。

这些记录是简短的角色状态，不是模型隐藏推理过程。人物的真实感不依赖宣称系统拥有意识。

## 人物自己的选择

稳定人物卡与虚构世界回答“她是谁”。当前 `moment` 记录感受、注意力、场景和 `intention`：她表达过的眼前打算。最多三条 `open_threads` 记录具体未完话题、归属与实际聊天来源；话题可以被记住，同时暂时不提。

普通聊天与自发联系共享这套状态。她可以主动提起自己的事、再聊一会儿、回去做自己的事，或结束这次交流。当地时间只是背景，生产代码没有“到了某点就必须说睡觉”的分支。真正有兴趣的事或重要求助也可以让她改主意。简短回复不代表生气，先前的一次争执也不应成为对后续所有问题的固定解读。

后台整理可以保留未完话题，移除已解决或明确撤回的事，并让旧情绪松动。它也会收到已经发出的角色回复及其来源 ID，避免把角色自己的打算记成用户的经历。来源会验证是否存在，语义是否准确仍取决于模型。未完话题不自动变成追问任务；每次普通回复仍只生成一次，不添加前置规划调用。

## 情绪、作息与暂离

`moment` 现在还记录 `energy`（精力）、`engagement`（当时交谈兴致）和 `cause`（情绪来由）。后台整理结合实际交流、已有生活记录与经过的时间更新这些字段。普通招呼不自动把低落重置成热情；对某个话题没兴致也不等于永久讨厌用户。没有随机心情抽签、好感度扣分或不回复惩罚。它仍是模型生成的叙事状态，原因是否准确需要评估。

作息是一段人物习惯，默认大约零点半休息、八点起床，可因为实际情境改变。自定义方式：

```sh
alivyn persona routine show
alivyn persona routine set '习惯一点休息，九点起床；下午工作时不常看消息。'
# 重启正在运行的渠道以加载设置。
```

同一次回复生成可以选择说话、留白、或带返回时间的暂离（休息、忙碌、独处）。`[[wait]]` 表示本轮不再发送，也不安排追问。开放暂离能力时，一次生成返回简短的 `mode/reply/absence` 对象：动作、实际消息、暂离参数。暂离携带种类、RFC3339 返回时间和简短理由，可以附带一句普通收尾，也可以直接延后当前回复。用户只看到实际消息。这个对象不包含思维链或整套心理状态；为避免部分服务商 JSON 模式出现空白输出，使用普通补全并在本地验证。旧的首行 `[[away:{...}]]` 格式仍可解析。执行器检查一分至十六小时的时间范围，把选择写入数据库；暂离期间普通消息不调用模型，主动联系也被阻止。

返回时重新读取待处理消息，最多八条合并理解，不发送睡前生成的过期回复。同一条已延后的消息不再安排第二次暂离；返回后一小时也不开放新的暂离动作。重启不会丢掉返回时间。`/状态` 可查看正在暂离的种类与时间，`/唤醒` 可提前恢复。

无人值守的延后回复目前只在 `character_v2` 的飞书运行进程中执行。终端仍能使用人物状态、作息、留白和控制命令，但没有后台返场发消息能力。离线期间不能发消息；重新联网运行后才处理到期队列。作息不是操作系统定时睡眠：是否决定暂离仍取决于模型，提示词不能保证她每晚都会按时离开。

## 控制台与诊断

所有命令必须单独发送，中英文等效。它们在消息入库时执行，不经模型；诊断的问答与暂停期间发来的普通文字不会进入人物记忆。一般聊天不会触发控制操作。

| 中文 | English | 用途 |
| --- | --- | --- |
| `/帮助` | `/help` | 查看可用命令 |
| `/状态` | `/status` | 运行模式、暂离与联系限制 |
| `/暂停` | `/freeze` | 暂停人物回复和主动联系，保留已有记忆 |
| `/唤醒` | `/wake` | 恢复人物、提前结束暂离；保留勿扰限制 |
| `/勿扰` | `/quiet` | 关闭主动联系 |
| `/允许主动` | `/contact on` | 允许自主判断联系，仍受安静时段及上限约束 |
| `/诊断` | `/diagnostics` | 申请查看内部记录 |
| `/确认诊断` | `/diagnostics confirm` | 在申请后 60 秒内确认，暂停人物并进入诊断 |
| `/取消` | `/cancel` | 撤销尚未确认的诊断申请 |
| `/人物` | `/persona` | 诊断中查看人物卡与虚构背景 |
| `/作息` | `/routine` | 诊断中查看作息习惯 |
| `/记忆` | `/memories` | 诊断中查看最近最多 20 条有效提取事实及来源 |
| `/心境` | `/state` | 诊断中查看最近保存的状态快照与时间 |
| `/挂念` | `/threads` | 诊断中查看未完话题与聊天来源 |
| `/返回角色` | `/resume` | 退出诊断，恢复进入前的运行或暂停状态 |
| `/清除记忆` | `/reset` | 立即执行下文所述的本机重置 |

查看的是已保存的设定或记录，不会临时调用模型扮演一场诊断。快照可能过期，事实提取也不是完整聊天记忆。诊断申请到期后不会自动进入。暂停、诊断与返回的效果跨重启保留；进入暂停或诊断会取消尚未发送的普通回复与主动联系，快速唤醒也不能让旧生成结果重新发送。开始发送的操作先完成，再执行控制命令；每个数据库只运行一个渠道进程。

控制方式借鉴《西部世界》中进入分析状态、暂停和返回人物的表达，使用独立斜杠命令实现；参见 [Ars Technica 的剧集讨论](https://arstechnica.com/video/watch/all-things-gaming-decrypted-westworld-episode-02-step-into-analysis-mode-please/) 与 [WIRED 的剧集回顾](https://www.wired.com/story/westworld-recap-season-2-episode-6/)。这不表示复现了剧中的意识设定。

## 恢复初始人物状态

在飞书、TUI 或普通终端聊天中，单独发送完整的 **`/清除记忆`** 或 **`/reset`**。命令立即在本地执行，不调用模型，也不靠角色口头承诺遗忘。

一次事务清除当前对话、提取的记忆、关系进展、人物状态、未完话题、虚构世界进度、暂离、诊断记录与待发送的联系记录，并恢复运行模式。初始人物卡、名字与世界配置、模型密钥、渠道连接、用户的联系限制保留。命令回执不会进入后续模型上下文；下一次交流从初始关系开始。

旧飞书事件只保留不含内容的去重标识，数据库 ID 不复用。清除前发起但尚未完成的生成结果会失效，旧的排队消息也会在发送前检查。同一渠道进程中，清除操作与最后的发送步骤同步：已经开始发送的操作先完成，清除完成后不再发送已失效的排队消息。每个本地数据库只运行一个渠道进程；这不是多进程分布式锁。

清除范围是当前本地数据库。飞书已有消息、模型服务商记录和独立备份有各自的保留机制；命令本身不为被清除的记忆创建备份。后台 API 判断预算属于运行设置，会保留，防止反复清除导致调用量失控。

## 对话节奏

飞书 v2 会把同一聊天中连续发来的消息视作一段话：等四秒空隙后合并，最长等待十二秒，每组最多八条。所有用户消息仍保留，最后一条作为回复锚点。生成前就持久化分组，重试和重启不会把它拆成逐条回答；准备好的回复不会被重新合并。分组确定后新来的消息属于下一段。这是有限的合并窗口，不是输入状态检测。

`internal/character/rhythm.go` 计算当前这一段的长度、最近双方的文字量和角色追问次数，并与原始对话一起提供给模型。小来小往默认只接一个短意思；近期说得太多、问得太多时，提示这一轮收住。它不通过关键词判断用户情绪，不机械截断文字，也不增加模型调用。认真倾诉、需要解释的问题仍可展开。

角色可以明确选择 `[[wait]]`，让已结束或没有兴致继续的随意话题自然停下。直接提问、初次招呼、纠错和求助仍应回应。运行时将这种选择记录为已处理的安静回合，与生成失败区分，不把标记发给用户。虚构生活也不等于现实设备能力，不能据此承诺拍照、发送附件或操作手机。

## 自发联系

启用 v2 并运行飞书渠道后，独立循环会结合人物卡、当前状态、真实对话、有来源的记忆和世界事件，判断是否有具体事情想说。可以跟进、分享、重联，也可以不联系。提议只记录简短主题和来源，不保存隐藏推理；普通回复仍只有一次直接生成。

初始规则较保守：

- 至少已经认识，且用户没有要求疏远；最近交流超过 72 小时不触发。
- 熟悉关系至少间隔 30 分钟，初识关系至少 45 分钟，另加固定的 0–10 分钟变化；已处理的安静回合也算交流结束。
- 调用模型前检查暂停、安静时段、日联系上限和待处理私聊。每 45 分钟最多判断一次，每个本地自然日最多四次判断，重启不重置预算。
- 提议须引用 1–3 条存在的来源，安排 5–60 分钟后再考虑发送，三小时过期；相同种类和来源组合在 72 小时内去重。
- 判断后、生成前、发送前重查。用户发来新消息会取消待发送的自发提议；生成阶段仍可选择不发。
- 已发过主动消息但用户还没回来时，不再自发追发，不升级为抱怨或索要回应。

原有面试、唤醒、世界进展各自保留触发条件，共用联系策略。以上新增限制针对自发联系。`serve` 仍是本地发件箱演示；新的模型判断在飞书运行进程中执行。机器睡眠或离线时无法继续运转。

`alivyn contact status` 显示是否具备判断条件；`contact pause` / `resume` 控制主动联系。`contact simulate` 用当前模型与密钥，在隔离数据库和虚拟时间下检查分享、忙碌、话题结束三种情况，会产生 API 费用，但不发送飞书消息、不修改真实历史。分享场景也允许模型决定不发，不是强制成功演示。

参考了 [astrbot_plugin_group_chat_plus](https://github.com/Him666233/astrbot_plugin_group_chat_plus) 将后台调度、时机判断、文本生成、冷却和普通回复协调分开的机制，独立用 Go 实现，未复制其源码或人物提示词。上游 README 明确私聊支持尚未完成；视频截图不能证明具体使用了哪套人物卡。类似名字的 [dsh-dafeiyu](https://github.com/QCYTSN/dsh-dafeiyu) 是显示 DeepSeek Harness 任务状态的桌宠，本身不调用模型，不能据此解释截图里的情绪对话。

## 启用与比较

```sh
alivyn actor set character_v2
# 重启正在运行的渠道；终端聊天在启动时读取配置。
alivyn chat

ALIVYN_AUDITION_REPORT=/tmp/character.json alivyn actor audition character_v2 all
ALIVYN_AUDITION_REPORT=/tmp/actor.json alivyn actor audition actor_v1 all
```

比较使用隔离数据库和当前模型密钥，不发送飞书消息，不改变真实角色。会产生模型 API 费用。报告完整保留回复、错误、生成耗时、生成调用次数与单独的后台整理结果。`ALIVYN_AUDITION_MODEL`、`ALIVYN_AUDITION_THINKING`、`ALIVYN_AUDITION_EFFORT` 可用于对比，不修改实际配置。

固定多轮场景覆盖初识、受挫、玩笑、日常连续性、欲言又止、记忆纠正、现实与能力边界、日常节奏、兴趣变化、自己的安排、未完话题与重置。新增 `low mood continuity` 检查预置低落心情的延续；`sleep and return` 用隔离飞书队列和虚拟时间保留实际选择、排队与返场结果（不会强制模型睡眠）。其中 `leaving an active chat` 预置一段已经说出的休息打算，用于检查选择能否延续，不要求所有深夜聊天都同样结束。这些是可检查的样例，不是“像真人”的量化证明。`alivyn actor set actor_v1` 可恢复上一版实验引擎，`legacy` 恢复原始引擎，均需重启渠道。评估期间，新安装仍默认使用 `legacy`。

## 已知不足

部分模型仍会误读暗含的玩笑、连续反问，或者用虚构的行程解释不存在的线下见面。提示词边界不等于事实验证器。单独一条漂亮回复不能证明整体体验。早期对照还观察到同时生成台词和状态时的 JSON 空白输出，因此状态整理被移出发送路径。

长期观点演化、开放式自主生活模拟和手机操作尚未由本引擎实现；世界进展仍是有边界的。后续应使用未参与调优的长对话、跨重启回忆、情绪变化评估，避免继续堆叠特定问候场景规则。

## 代码入口

`internal/character/`：中英文提示词、默认人物卡、直接对话与后台整理。`internal/session/character.go`：按来源组装上下文与后台任务。`internal/store/character.go`：草稿、已提交回复、过期状态与世界事件回执。`internal/model/`：模型接口；自定义兼容服务默认不接收 DeepSeek 专有思考参数。
